C3 的三個風險與對策

都是實測發現,導入時要處理(監控元件在 demo 已啟用 HTTPS + Basic)
🔑
c3 的憑證 = 管理員
實測:換到的 token 可建立 / 刪除 role binding(204)
對策:嚴控 client-c3 keystore 權限;User:c3 列入受保護清單
📈
Prometheus 的 Basic 帳密
實測:不帶帳密 401;有帳密就是完整讀寫
對策:帳密依用途分開;C3 日誌會印出 Authorization 標頭,日誌要保護
🔔
Alertmanager 的 Basic 帳密
實測:不帶帳密建立靜音 401;帶帳密才能建立與刪除
對策:C3 與 OP menu 用不同帳號;網路隔離 + 監看靜音變更
官方文件:C3 的 MDS 憑證範例是帳密、且說 C3 以自己的主體查詢 Kafka;本環境用憑證、使用者操作帶使用者身分(實測)
