CA 要簽 server 與 client 憑證?

server:1 張共用。client:平台元件 c3、restproxy、bootstrap,加上每個經 REST Proxy 的 legacy app 各 1 張。

broker / controller 之間用 mTLS?

本方案:SASL over TLS(controller 間 PLAIN、broker 間 SCRAM)。共用憑證做 mTLS 只會得到同一個 principal;客戶日後有專用內部憑證才改 mTLS。

⚠ 與原稿不同,待確認;多 controller 間 PLAIN 未實測

串接的 client 來自不同 CA root?

把該 client 的 CA root 匯入 truststore 即可。

已知風險與對策

補充內容

c3 憑證 = 管理員

發現:能建立 / 刪除 role binding;拿掉它的權限 C3 會退出(實測)

對策:保護私鑰與檔案權限;列入受保護清單

REST Proxy 憑證可代人

發現:可代任何不在保護清單的使用者;清單混入 Group: 會整份失效(實測)

對策:特權身分逐一以 User: 列入

Prometheus / Alertmanager

發現:demo 未啟用認證,Alertmanager 可無認證寫入靜音

對策:官方支援 TLS + Basic;未啟用時以網路隔離

broker 內建 Admin REST

發現:未設安全擴充時匿名可進入(本 demo 實測);曾使 broker OOM

對策:依官方 kafka.rest. 設定後,匿名回 401
